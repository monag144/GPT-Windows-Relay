Windows counterpart to the phone GPT-Termux relay.

## Loop

```text
ChatGPT assistant message in Firefox
 -> extension reads an exact GPT_WINDOWS_ACTION packet
 -> authenticated localhost request to 127.0.0.1:8766
Windows relay
 -> validates + reserves operation id
 -> executes PowerShell / pwsh / cmd
 -> returns GPT_WINDOWS_RESULT
extension
 -> inserts result into ChatGPT composer
 -> clicks Send
 -> ChatGPT continues
```

## Safety

- Starts **ARMED** and returns ARMED after supervised recovery, per current runtime policy.
- Browser extension scans **assistant messages only**, never arbitrary page/user text.
- Exact `GPT_WINDOWS_ACTION` markers are required.
- `platform` must be exactly `windows`.
- Only `EXEC` is enabled.
- Server binds only to `127.0.0.1`.
- Random bearer token is generated by `install.ps1`.
- Operation IDs are durably reserved before execution, preventing duplicate replay.
- Command length: 20,000 characters max.
- Timeout: 300 seconds max.
- Browser-facing results default to compact previews: stdout 1,800 chars, stderr 1,200 chars.
- Full stdout/stderr is saved locally under the relay state directory before browser previewing.
- Set `"result_mode": "full"` on a packet when a larger browser-visible result is genuinely needed; legacy network caps remain 30,000 characters per stream.
- Timed-out processes are terminated as a Windows process tree.

When armed, this is intentionally powerful: ChatGPT can run commands as your Windows user.

## Packet

```text
[GPT_WINDOWS_ACTION]
{
  "version": 1,
  "platform": "windows",
  "action": "EXEC",
  "id": "unique-operation-id",
  "session": "default",
  "shell": "powershell",
  "cwd": "C:\\Users\\YourName\\Projects",
  "timeout": 120,
  "command": "git status",
  "result_mode": "compact"
}
[/GPT_WINDOWS_ACTION]
```

`shell` may be `powershell`, `pwsh`, `cmd`, or `python`. `result_mode` is optional and defaults to `compact`; use `full` only when the browser genuinely needs the larger payload.

For command payloads, provide exactly one of:

- `command`: ordinary string command; preferred for short/simple commands.
- `command_lines`: JSON array of strings joined by the relay with newline characters.
- `command_b64`: UTF-8 command bytes encoded as Base64.

### Payload transport policy

The relay is **Python-first for complex engineering work**, but Base64 is the **permanent backup transport**.

Preferred order:

1. Use plain `command` when the command is short and quoting is simple.
2. Prefer `shell: "python"` (with `command` or `command_lines`) for complex, multiline, file-management, test, build, and orchestration work.
3. Fall back to `command_b64` whenever JSON/CMD/PowerShell quoting, multiline pasting, terminal rewriting, or transport integrity becomes unreliable.

`command_b64` is not deprecated and must not be removed as dead compatibility code. It is the relay's original resilient transport path and remains the emergency/compatibility fallback when higher-level command transport misbehaves.

When `shell` is `python`, the relay executes the decoded/reconstructed command directly with its own Python runtime using `python -c`. This makes multiline Python available without nesting Python inside PowerShell.

## Why a browser extension instead of generic Windows screen scraping?

The current Windows machine is using ChatGPT in a browser. The extension gives us a stronger equivalent to Android AccessibilityService: it can deliberately inspect only assistant messages and fail closed when ChatGPT's DOM changes. Generic Windows UI Automation cannot reliably tell an assistant relay packet from a packet quoted by the user or another application.

A native ChatGPT-desktop UI Automation adapter can be added later without changing the executor or packet protocol.

## Recovery behavior

The browser bridge is designed for zero-intervention recovery after initial persistent-extension setup:

- scanner V11 performs one recovery-only scroll to the newest valid assistant relay command, then manual scrolling remains authoritative
- action requests retry transient localhost failures for up to 45 seconds
- if a command completed but its HTTP response was lost, retrying the same operation ID replays the saved result instead of executing the command twice
- the relay supervisor/watchdog restores the backend ARMED
- the production Firefox path is the signed persistent extension (`extension-persistent`; current version is tracked by its manifest) installed with `ExtensionSettings` in `force_installed` mode
- the persistent extension keeps its pairing token in `chrome.storage.local`, so normal Firefox restarts do not require re-pairing

The temporary extension loaded through `about:debugging` is development-only and, by Firefox design, disappears after a full browser exit. Standard Firefox release builds require Mozilla signing for permanently installed extensions. The persistent XPI therefore must be signed (for example as an unlisted AMO extension) before the policy installer can make Firefox restarts fully zero-touch.
