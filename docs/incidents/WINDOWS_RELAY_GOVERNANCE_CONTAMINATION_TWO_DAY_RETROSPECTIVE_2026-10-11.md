## Proven technical cause and architecture correction
1. Two distinct responsibilities were improperly coupled: **assistant engineer governance** (GitHub audits every five issued operations, twenty-operation review, unique IDs and evidence provenance) and **Windows runtime permission/execution** (token, operator authorization, legitimate owner, STOP/disarm, atomic reservation, collision/dedupe).
2. The installed PCE17 nested legacy dispatcher invoked the harness without its required GitHub receipt and therefore deterministically blocked multiples of five. Adding more audit files alone couldn't repair its missing function argument. Older branches also carried stale harness signatures and unexpected compatibility filename requirements.
3. Canonical WIP root `windows-relay/windows_relay.py` **does not invoke** `engineering_preflight` in its dispatcher. Source-level regression `windows-relay/tests/test_dispatcher_no_audit_gate.py` was committed at `b85e26678065795338c2676cbe526dec0c75bb83`, but earlier evidence **did not include running that regression on the loaded backend**. The current status must be proved by testing, not assumed.
4. **Permanent policy:** Keep GitHub-first audits and reviews as engineering accountability. **Do not** let numbered PCE checkpoint/audit presence, locally cached GitHub documents, or outdated governance definitions become a runtime execution gate. This is not permission to remove authenticated transport, owner binding, STOP/KILL interlocks, exact-once controls or a genuinely safe operator approval boundary. Never forge a receipt as a workaround.

## Required no-regression tests (not claimed completed)
- Assert static and runtime dispatcher paths never consult `engineering_preflight`, `github_audit_receipt`, cached GitHub audit files, or ordinal-modulo-5 checks while admitting authenticated Windows actions.
- Test safe no-side-effect commands with unique IDs at `.004→.005→.006`, `.009→.010→.011`, `.014→.015→.016`, `.019→.020→.021` and another window after a process restart. **Passing the fifth slot requires no local/GitHub audit receipt in POST /action**. No prior issued ID may be reused.
- Independently test negative security cases: unpaired/wrong bearer token, missing or forged issuance/owner, cross-conversation owner, STOP/OFF/KILL, duplicate and collided ID, crash-before/after claim, retained ledger after restart. These **must** still reject unsafe commands.
- Capture native backend path/hash, extension loaded identity, result persisted/delivered, HUD outcome and operator rescue count. A displayed `RESULT READY` without success is not acceptance. Keep browser-transport defect (missing `issuance` and `owner` in WIP persistent worker) separate: [PCE17.022 incident](WINDOWS_RELAY_PCE17_022_CODEX_LAUNCH_ACTION_FAILED_2026-10-11.md).
- Run the actual full suite, write failing test names and error text, separately grade live command delivery/STOP/exact-once and long-duration endurance. **A full unit pass without witnessed live sends does not justify a release.**

## Prevent repeat and protect operator time
- **Single source:** Windows Relay engineering belongs to `GPT-Windows-Relay-Main-Build` and `monag144/GPT-Windows-Relay`; old `GPT/Client/Relay` and `runtime/` code are provenance/rollback or a protected installed runtime **until verified retired**. Never rely on stale `current.md`, `active.md`, stale PCE10 roadmap text, or a Termux copy as live authority.
- **Escalate earlier:** after the **first** verified mismatch between committed GitHub audit and a runtime governance rejection, stop creating more compatibility paperwork. Inspect backend executable/script path, preflight call signature, actual loaded harness bytes and exact input arguments. Record once, isolate, repair canonical code and add a regression.
- **Operator experience:** do not force long PowerShell copy/paste or keep trying the same failing command; use bounded native read-only diagnostics, independent CMD runner when necessary, and record exact outcomes. Avoid repeated low-value governance loops and produce measurable net-new progress toward working product.
- **Never replay unknown work:** blocked/failed IDs remain consumed; check durable state before ever scheduling side-effectful Codex commands, cutovers or result delivery.
- **No autonomous agent switching**: retired by user directive; do not conflate source-governance validation with operator-authorized new-chat handoff.
- **Release gate:** no live cutover/cleanup claim until test failures are resolved, secure extension↔backend transport is proven, true loaded code identity and one visible exact result confirmed, STOP/ownership/exact-once verified and rollback tested.
