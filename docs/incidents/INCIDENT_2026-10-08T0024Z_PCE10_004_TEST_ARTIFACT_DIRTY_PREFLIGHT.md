# PCE10.004 test-artifact dirty-preflight incident — 2026-10-08T0024Z

## Observation

PCE10.004 failed before fetch/test/live mutation because the canonical Windows clone reported only:

- `consumer/__pycache__/`
- `consumer/tests/__pycache__/`

as untracked worktree dirt.

Those directories were generated by the preceding Python unittest/compile acceptance work.

## Classification

**HARNESS / REPOSITORY HYGIENE DEFECT**

The repository root had no `.gitignore`. Python artifact ignores existed only under `windows-relay/.gitignore`, so tests in `consumer/` created untracked artifacts that the next fail-closed preflight interpreted as unexplained source contamination.

## Impact

- no source mutation occurred locally;
- no live relay mutation occurred;
- no rollback is required;
- one engineering operation was consumed without advancing acceptance.

## Corrective rule

1. Add root-level ignores for deterministic Python/test caches across all repository subtrees.
2. Never use blind cleanup to make a dirty preflight pass.
3. On recovery, classify every dirty path first. Only known generated caches may be removed automatically; any other path fails closed.
4. Prefer bytecode-free acceptance execution where practical so source tests do not create the next preflight failure.
