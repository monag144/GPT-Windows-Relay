# PCE10 five-operation audit — operations 000 through 004

Audit cadence: mandatory five-operation boundary before PCE10.005.

## Scope

Reviewed PCE10.000, .001, .002, .003, and .004 against Control Harness v3, incident records, canonical-repository rules, test evidence, rollback discipline, and current roadmap.

## Findings

### PCE10.000

- Successor bootstrap did not continue autonomously after the identity operation.
- Director intervention was required.
- Pending-queue behavior later required another Director restart/continuation intervention.
- This violated the zero-babysitting mission and is already separately incident-logged.

### PCE10.001

- Failed before mutation because an intended canonical clone path was treated as proof that the clone already existed.
- Corrective lesson: discover repository identity by Git remote, or create the canonical Windows clone deliberately.

### PCE10.002

- Failed before mutation because an ad-hoc desktop UIA Firefox scanner rediscovered browser lifecycle state instead of using the established managed Firefox adapter.
- Corrective lesson: established lifecycle facts/adapters are authoritative unless browser state actually changes or a named gate requires re-proof.

### PCE10.003

- Required control files were read and canonical Windows clone was reached.
- Targeted tests failed closed before live mutation.
- Root cause: over-escaped Python PCE ordinal regex plus a duplicate legacy JavaScript `operationOrdinal` definition overriding the engineering-aware parser.
- Structural singleton test and corrected regexes were added.

### PCE10.004

- Failed before mutation because test-generated `consumer/**/__pycache__` directories appeared as untracked dirt.
- Root cause: repository-level ignore policy was missing outside `windows-relay/`.

## Cross-cutting assessment

Safety behavior is working: operations .001 through .004 all failed before live mutation, so no uncertain side effect or rollback ambiguity was introduced.

Harness quality was not good enough: four consecutive operations exposed assumptions that should have been encoded as reusable controls rather than rediscovered in operation packets.

Repeated/disproven approaches identified:

- guessed workspace existence;
- duplicate/ad-hoc Firefox window discovery;
- layered regex escaping without structural singleton proof;
- test execution that creates unignored source-tree artifacts.

User rescue count is above the acceptable baseline because bootstrap/continuation required Director intervention.
