## Confirmed source-level release blocker, not a live incident

The existing process method deduplicates against `state.data['processed']`, but the `State.mark` 500-entry eviction removes processed IDs for SUBMITTED and SUBMIT_UNCERTAIN outbound states (and for records lacking an outbound delivery). Outbound records alone do not guard `process` prior to `execute`. At PCE15.047, a changed-payload retry reached **synthetic execute before** `RelayError('outbound delivery id collision')`. This is a reproducible **source-level replay-after-eviction safety flaw**, independent of earlier PCE15.043 demonstrated concurrent check/then/reserve race. There is **no evidence of actual repeated shell commands or ChatGPT sends**, and the running module byte identity remains unverified.

New focused incident: `docs/incidents/INCIDENT_2026-10-10T0304Z_PCE15_DEDUP_RETENTION_POST_EVICTION_REPLAY.md`; prior concurrency/owner incident: `docs/incidents/INCIDENT_2026-10-10T0250Z_PCE15_NONATOMIC_ACTION_CLAIM_AND_OWNER_GUARD_GAPS.md`.

**Remediation design only, no authorization to modify runtime:** atomic same-ID claim + durable immutable payload tombstone before execute; consult processed, outbound, and identity ledger under appropriate coordination; never erase a replay-protection identifier merely to bound the 500-entry result display cache; fail closed on persistence errors and uncertain restart; reason about process-level locking, durable transactions and outbound response reconciliation. Preserve governance, operator STOP/ARM behavior, distinct ID collision semantics, loaded browser extension binding, signed release packaging and independent runtime tests.
