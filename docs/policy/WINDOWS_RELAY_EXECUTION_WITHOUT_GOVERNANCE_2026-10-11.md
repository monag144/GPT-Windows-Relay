# Windows Relay execution without governance — 2026-10-11 (Pacific)

**CURRENT OPERATOR DIRECTIVE:** Windows Relay command execution has **no governance requirement**. No GitHub audit, receipt, mandatory roadmap/source read, PCE ordinal modulo-five/20 checkpoint, benchmark, documentation review or engineering preflight may block a valid authorized command. The backend must not consult the consumer control harness for audit admission. A legacy compatibility function is nonblocking.

**Runtime security is different from governance and stays enforced:** authenticated token/localhost transport, positive operator authorization, correct conversation/session owner, STOP/OFF/KILL, atomic action claim, ID collision and replay prevention, approval for consequential operations, and safe rollback. Removing audit bureaucracy does not authorize unsafe execution.

**Engineering testing, benchmarking and incident logging are separate, optional workflows, not execution gates.** Historical strict 11/28 benchmark measures accepted release evidence, not 11/28 passing unit tests. Offline suites of 98/98 and 129/129 passed yet did not prove real message delivery. Periodic audit/review paperwork is not mandatory. Original dated audit and incident records remain history, never operative instructions.
